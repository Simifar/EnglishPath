# Модель каталога

Каждый файл src/data/{levels,textbooks,resources,exams}.ts содержит самостоятельный массив явных объектов. Источник типов — Zod-схемы в types.ts, без параллельных интерфейсов и вычисления данных из заголовков.

## Добавление и изменение

1. Выберите постоянные уникальные id и slug. Меняйте название независимо от них. Все ID, включая темы, должны быть уникальны во всём каталоге.
2. Добавьте объект в соответствующий массив. Каталог, поиск, избранное и детальные маршруты используют эти массивы автоматически; новая сборка создаёт страницу.
3. Для отображения рекомендации в плане добавьте ID книги в textbookIds или ID ресурса в resourceIds. Не дублируйте описание материала внутри плана.
4. Задавайте HTTP(S)-адрес без учётных данных. Валидация проверяет синтаксис и протокол, но не легальность источника и не доступность страницы.
5. Не ставьте дату проверки автоматически. verifiedAt — дата предметной проверки, linkCheckedAt — дата проверки внешнего адреса. pending не может иметь verifiedAt. verified требует обе даты; для книг и ресурсов — также аудиторию, инструкцию, ограничения и определённое требование регистрации.
6. Запустите bun test, bunx tsc --noEmit, bun run lint, bun run validate-content и bun run build. Проверьте новую страницу и связи вручную.

## Неизвестные данные

- registration и hasAnswers: yes / no / unknown.
- audience, howToUse, format ресурса, edition книги: строка либо null, если ещё не установлено.
- limitations: null — не проверено; [] — проверено, известных ограничений не записано.
- access: free / mixed / paid. Унаследованное значение у pending-записи ещё требует редакционной проверки.
- cefrLevels ресурса: [] вместе с levelStatus: unassessed. При выборе диапазона задайте levelStatus: assessed и хотя бы один уровень. Не назначайте A1–C2 по умолчанию.
- skillAreas ресурса: явные навыки из перечня в types.ts. [] означает, что навыки ещё не размечены.

Неуточнённый уровень отображается на странице ресурса и в поиске. Такой материал находится общим поиском, но не проходит фильтр конкретного уровня.

## Пример ресурса до проверки

Это шаблон, example.com нужно заменить реальным официальным источником до публикации.

```ts
{
  id: 'resource-example',
  slug: 'resource-example',
  title: 'Пример ресурса',
  description: 'Собственное краткое описание назначения.',
  cefrLevels: [],
  levelStatus: 'unassessed',
  tags: ['чтение'],
  category: 'reading',
  skillAreas: ['reading'],
  format: null,
  access: 'free',
  registration: 'unknown',
  officialUrl: 'https://example.com/reading',
  reviewStatus: 'pending',
  verifiedAt: null,
  linkCheckedAt: null,
  audience: null,
  howToUse: null,
  limitations: null,
}
```

У книг дополнительно обязательны authors, publisher, series, format, purpose, edition и hasAnswers. У планов — группы grammar/vocabulary/skills и массивы textbookIds/resourceIds. Полный перечень — в src/data/types.ts.

## Миграция 9 сентября 2026

Сохранены 51 ID/slug опубликованных материалов, 88 тем и прежние связи с книгами. До миграции книги и ресурсы вычислялись из legacyLevels/legacyWebsites; теперь названия, авторы, издатели и серии заданы непосредственно в объектах.

Редакционные сведения перенесены без попытки выдать эвристики за проверенные факты. Массовые старые даты и автоматические диапазоны ресурсов сняты с публикации; прежние значения сохранены в docs/catalog-before-model-migration.json для сверки. Текущие записи ожидают редакционной проверки этапа 4. Новые рекомендации через resourceIds пока не отобраны: массивы пустые, валидация и отображение связей готовы.

Регрессионный тест сверяет опубликованные адреса с docs/catalog-baseline.json и якоря/книжные связи со снимком. Новые записи добавлять можно; удаление или смена старого адреса требует продуманной миграции и обновления теста, а не простой перегенерации baseline.
